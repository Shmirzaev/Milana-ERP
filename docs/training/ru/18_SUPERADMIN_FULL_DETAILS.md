# Полное учебное руководство Super Admin

Версия: 1.0
Дата: 2 июля 2026 г.
Код отдела: ADM
Роль: Super Admin

## Цель

Super Admin имеет высший уровень доступа ERP. Super Admin может делать все, что может делать администратор, а также функции, доступные только Super Adminу, такие как доступ MCP и консоль необработанных данных.

Используйте эту роль только для доверенных владельцев системы. Не используйте Super Admin для обычной повседневной работы отдела.

## Доступ Super Adminа

Super Admin идентифицируется:

1. Имя роли `Super Admin`.
2. Разрешение `admin.super`.

Заданные права Super Adminа:

1. `*`
2. `admin.super`

Разрешение `*` предоставляет полный доступ к приложению ERP. Разрешение `admin.super` открывает разделы, доступные только Super Adminам.

## Суперстраницы только для администраторов

- MCP Access
- Data Console

Super Admin также имеет доступ ко всем обычным страницам приложения, включая пользователей, отделы, журналы аудита, настройки, информационные панели, производство, финансы, расчет заработной платы, закупки, инвентаризацию, отслеживание и все страницы отделов.

## Первый бутстрап администратора

При настройке процесс заполнения создает загрузочного пользователя Super Admin.

Важные правила:

1. `INITIAL_ADMIN_PASSWORD` должен быть установлен для активации первого администратора.
2. Общие пароли демо/администратора по умолчанию заблокированы для реальной учетной записи администратора.
3. `INITIAL_ADMIN_EMAIL` может установить первый адрес электронной почты администратора.
4. Демо-пользователи создаются только при наличии `SEED_DEMO_USERS=true`.
5. Примеры клиентов/материалов/моделей/заказов создаются только при наличии `SEED_SAMPLE_DATA=true`.

## Администрирование пользователей

Super Admin может создавать учетные записи администратора и Super Adminа и управлять ими. Обычным администраторам запрещено назначать контроль Super Adminа.

Создание пользователя:

1. Откройте Пользователи.
2. Введите имя и адрес электронной почты.
3. Выберите роль.
4. Выберите отдел.
5. Создать пользователя.
6. Подтвердите процесс настройки электронной почты и пароля в соответствии с политикой развертывания.

Пользовательское редактирование:

1. Откройте редактирование пользователя.
2. Обновить имя/адрес электронной почты.
3. Устанавливайте новый пароль только в том случае, если это разрешено политикой.
4. Сменить роль.
5. Отдел смены.
6. Добавьте или удалите дополнительные разрешения.
7. Активировать/деактивировать.
8. Сохранять.

Правила Super Adminа:

1. Имейте хотя бы одну активную учетную запись Super Adminа/администратора.
2. Не назначайте `*` или `admin.super` временным пользователям.
3. Отключайте аккаунты сразу, когда человек уходит.
4. Просмотрите информацию о последнем посещении/последнем входе в систему для устаревших привилегированных учетных записей.
5. Избегайте совместного использования одной учетной записи Super Adminа.

## Модель разрешения

Роли содержат разрешения. Пользователи также могут иметь дополнительные разрешения.

Основные категории разрешений:

1. Продажи: `sales.orders`, `sales.customers`.
2. Планирование: `planning.view`, `planning.requirements`, `planning.production`, `planning.reserve_materials`, `processes.view`, `sewing.flows`.
3. Моделирование: `modeling.models`, `modeling.bom`, `modeling.brands`, `modeling.collections`, `modeling.approve`.
4. Производственный этаж: `cutting.records`, `cutting.bundles`, `printing.records`, `printing.bundles`, `sewing.records`, `sewing.bundles`, `packaging.records`, `packaging.packages`, `production.override_deadline`.
5. Хранение и отгрузка: `storage.receive`, `storage.transfer`, `storage.items`, `storage.suppliers`, `storage.packages`, `storage.shipment`.
6. Финансы: `finance.view`, `finance.invoice`, `finance.payment`.
7. Кадры и расчет заработной платы: `hr.employees`, `payroll.view`, `payroll.manage`, `payroll.approve`, `payroll.pay`, `payroll.scan`.
8. Покупка: `purchasing.view`, `purchasing.request`, `purchasing.approve`, `purchasing.order`, `purchasing.receive`.
9. Отходы: `waste.receive`, `waste.sell`, `waste.disposal`.
10. Руководство / Админ: `management.view`, `management.approve`, `admin.users`, `admin.audit`, `admin.super`, `tasks.manage`.
11. Прослеживаемость/прогнозирование: `traceability.view`, `traceability.export`, `forecasting.view`, `forecasting.manage`.
12. Резервирование инвентаря: `inventory.reservations.view`, `inventory.reservations.create`, `inventory.reservations.release`, `inventory.reservations.consume`.

Сначала используйте роли. Используйте дополнительные разрешения только для преднамеренных исключений.

## Data Console

Data Console предназначена только для Super Adminа и предоставляет доступ к таблицам базы данных через `/api/admin/super-data`.

Возможности:

1. Перечислите все таблицы.
2. Просмотр количества строк.
3. Поиск строк.
4. Редактировать редактируемые столбцы.
5. Удалить строки.
6. Просмотр типа столбца, первичного ключа, внешнего ключа, обнуляемых и редактируемых метаданных.

Ограничения:

1. Первичные ключи доступны только для чтения.
2. Двоичные столбцы доступны только для чтения.
3. Таблицы без первичного ключа с одним столбцом нельзя редактировать/удалять через эту консоль.
4. Ограничения базы данных могут блокировать обновления/удаления.
5. Обновления и удаления Super Data регистрируются в журнале аудита.

Правила безопасности Консоли данных:

1. Для исправлений отдавайте предпочтение обычным страницам ERP.
2. Используйте Data Console только при отсутствии нормального рабочего процесса.
3. Проверьте связанные записи перед редактированием внешнего ключа.
4. Никогда не удаляйте производственные записи случайно.
5. Не редактируйте финансовые записи, отчеты о заработной плате или аудиторские записи без письменного разрешения.
6. Сделайте резервную копию или экспортируйте данные перед рискованным массовым исправлением.
7. Измените одну строку, проверьте и продолжайте.
8. Запишите причину во внешнем журнале изменений или задаче.

## MCP Access

MCP Access предназначен только для Super Adminа и отображает сведения о настройке Milana ERP AI GM Assistant.

На странице показано:

1. Имя сервера.
2. Отображаемое имя.
3. ERP API базовый URL.
4. Транспорт.
5. Модуль Python.
6. Имя пакета.
7. Примечания к доступу во время выполнения.
8. Заполнители среды.
9. Конфигурация Клода Десктоп.
10. Прочтите инструменты.
11. Писать инструменты.
12. Примечания по безопасности.
13. Заблокированные действия.

Правила токена MCP:

1. Используйте настоящий токен носителя ERP для учетной записи GM/Super Adminа только при необходимости.
2. Не вставляйте действующие учетные данные в снимки экрана, заявки или чат.
3. Поменяйте токен/пароль, если он раскрыт.
4. Инструменты MCP по-прежнему подчиняются разрешениям ERP API.
5. Заблокированные действия должны оставаться заблокированными, пока владелец продукта явно не изменит политику.

## Системные настройки

Super Admin может обновить настройки:

1. Название компании.
2. Логотип компании.
3. Адрес.
4. Телефон.
5. Электронная почта.
6. Валюта по умолчанию.
7. Месяц начала финансового года.
8. Язык по умолчанию.
9. Часовой пояс.
10. Варианты типа модели.
11. Требуйте резервирования материала перед резкой.

Ударопрочная настройка: перед резкой требуется резервирование материала. Если этот параметр включен, резку можно заблокировать до тех пор, пока не будут зарезервированы материалы BOM. Включайте его только после обучения хранению, планированию и резке.

## Аудит и расследование

Поддержка журналов аудита:

1. Поиск.
2. Фильтровать по пользователю.
3. Фильтровать по действию.
4. Фильтровать по типу объекта.
5. Фильтровать по идентификатору объекта.
6. Фильтровать по диапазону дат.
7. Показать детали со значениями до/после.
8. Экспорт/проверка конечных точек хэш-цепочки существует для рабочих процессов аудита целостности.

Процесс расследования:

1. Определите затронутую сущность и идентификатор.
2. Открытые журналы аудита, отфильтрованные по объекту и идентификатору.
3. Пересмотрите график.
4. Сравните значения до и после.
5. Определите пользователя, действие и основную причину.
6. Исправьте, используя обычную страницу, где это возможно.
7. Используйте консоль данных только в том случае, если обычная страница не может это исправить.
8. Задокументируйте исправление.

## Информация о резервном копировании и восстановлении

Super Admin должен знать, где находятся документы по готовности к работе, аварийному восстановлению, безопасности, конфиденциальности/хранению и архитектуре:

1. `docs/PRODUCTION_READINESS.md`
2. `docs/DISASTER_RECOVERY.md`
3. `docs/SECURITY_RUNBOOK.md`
4. `docs/PRIVACY_RETENTION.md`
5. `docs/ARCHITECTURE.md`

Прежде чем выполнять рискованное обслуживание данных, подтвердите доступность резервной копии и план отката.

## Правила безопасности

1. Используйте надежные пароли.
2. Не делитесь привилегированными учетными записями.
3. Сохраняйте минимальное количество Super Adminов.
4. Регулярно проверяйте активные привилегированные учетные записи.
5. Отключите неактивные привилегированные учетные записи.
6. Защитите токены интеграции.
7. Не обходите журналы аудита.
8. Используйте параметры безопасности HTTPS/публичного развертывания при доступе к Интернету.
9. Не запускайте демо-пользователей в производство.
10. Не включайте образцы данных в производство.

## Когда использовать Super Admin

Используйте Super Admin для:

1. Создание или исправление доступа администратора/Super Adminа.
2. Просмотр настройки MCP.
3. Исправление консоли аварийных данных.
4. Расследование критических проблем аудита или целостности данных.
5. Настройки системного уровня.
6. Координация восстановления.

Не используйте Super Admin для:

1. Обычный вход в продажу.
2. Нормальный объем производства.
3. Обычное сканирование заработной платы.
4. Обычный прием.
5. Любое действие, которое роль отдела может безопасно выполнить.

## Ежедневный/еженедельный контрольный список Super Adminа

Ежедневно:

1. Проверьте работоспособность системы и доступность входа в систему.
2. Просмотрите любые срочные запросы на доступ.
3. Просмотрите неудачные или заблокированные критические процессы.
4. Проверьте изменения привилегированной учетной записи.
5. Просмотрите нерешенные высокоприоритетные задачи.

Еженедельно:

1. Просмотрите пользователей с правами администратора/Super Adminа.
2. Просмотрите пользователей, не использующих систему.
3. Просмотрите журналы аудита на предмет удалений и привилегированных изменений.
4. Проверьте статус резервного копирования.
5. Просмотрите изменения настроек.
6. Проверьте работоспособность интеграции.
7. Подтвердите пробелы в обучении у руководителей отделов.

## Контрольный список для экстренной коррекции

1. При необходимости остановите затронутый физический процесс.
2. Определите точные записи и идентификаторы.
3. Просмотрите журналы аудита.
4. Подтвердите желаемое исправление у владельца отдела.
5. Предпочитайте обычную коррекцию страницы.
6. Если требуется консоль данных, редактируйте по одной строке за раз.
7. Проверьте последующие записи.
8. Добавьте задачу/заметку с описанием исправления.
9. Уведомить затронутые отделы.

## Распространенные риски Super Adminа

| Риск | Профилактика |
| --- | --- |

| Предоставление слишком большого доступа | Используйте минимальные привилегии и доступ на основе ролей. |
