# HR And Payroll Training Manual

Version: 1.0
Date: 2026-07-02
Department code: HR
Default role: HR

## Purpose

HR maintains employee records and manages payroll periods, payroll records, and payroll adjustments. HR coordinates with Admin when an employee needs ERP login access.

## Main Pages

- Employees
- Payroll Summary
- Payroll Scan
- Admin Employees, where available
- Users, through Admin when login access is needed

## Key Permissions

- `hr.employees`
- `payroll.view`
- `payroll.manage`

## Employee Records

Employee fields:

1. Full name.
2. Position.
3. Department.
4. Phone.
5. Salary.
6. Status: active, inactive, on leave, or terminated.
7. Joined date.

## Employee Workflow

1. Open Employees.
2. Search existing employees first.
3. Add new employee with correct department and status.
4. Update position, phone, salary, and status when changed.
5. Set terminated/inactive employees correctly.
6. Ask Admin to create or disable ERP user login when needed.

Employee record and ERP user account are related but not the same thing. HR owns employee data; Admin owns login access.

## Payroll Scan Workflow

Payroll Scan is used for piecework or work-unit pay.

1. Open Payroll Scan.
2. Scan employee QR badge first.
3. Confirm current employee.
4. Scan work/process QR.
5. Review model, production, batch, operation, quantity, rate, and total.
6. Save latest scan or Save All.
7. Export CSV only when needed for local review.
8. Clear local scan session after saved records are confirmed.

Important: local scan history is not enough. Records must be saved to Payroll.

## Payroll Periods

Payroll Summary supports payroll periods.

1. Create period with name, start date, end date, status, and notes.
2. Keep active period open while scans are being collected.
3. Lock period when scanning is complete and review starts.
4. Management approves period.
5. Finance marks approved period paid after payment.

Statuses:

| Status | Meaning |
| --- | --- |
| draft | Period prepared but not active. |
| open | Records and adjustments can be added. |
| locked | Review is in progress; normal edits are closed. |
| approved | Management approved payroll. |
| paid | Finance marked payroll as paid. |
| cancelled | Period no longer active. |

## Adjustments

Adjustments are bonuses or deductions.

1. Select period.
2. Select employee.
3. Choose bonus or deduction.
4. Enter amount.
5. Enter reason.
6. Save.

Adjustments cannot be added to finalized periods: locked, approved, paid, or cancelled.

## Reviewing Payroll

Use filters:

1. Period.
2. Employee.
3. Department.
4. From date.
5. To date.

Review:

1. Records count.
2. Pieces.
3. Piecework amount.
4. Adjustments.
5. Net payroll.
6. Employee totals.
7. Operation totals.
8. Payroll records.

Void records only when the scan is wrong and local policy allows it. Paid payroll records should not be changed except by authorized admin procedure.

## Common Problems

| Problem | Likely cause | Action |
| --- | --- | --- |
| Employee cannot be selected in payroll | Employee record inactive/missing | Check Employees page. |
| Payroll scan says unknown QR | Wrong label or damaged QR | Reprint/verify employee or process QR. |
| Duplicate scan | Same work QR already saved | Check saved/duplicate status. |
| Cannot add adjustment | Period finalized | Reopen only if authorized; otherwise create next-period adjustment. |
| Employee needs ERP login | HR record is not a user account | Ask Admin to create user and assign role/department. |
